# Rule 02: SRE & Production Reliability Guardrails

## 1. Zero-Crash & Graceful Degradation Policy
* An unhandled exception or LLM failure must NEVER result in an HTTP 500 error seen by the shopper.
* **Circuit Breakers**: If an LLM provider fails, times out, or exceeds 2.5 seconds, the system must trigger an automatic fallback:
  1. Fast heuristic/semantic search fallback.
  2. Friendly customer service message ("I'm checking our catalog right now...").
  3. Never crash the shopping cart or store navigation.

## 2. Strict Input & Tool Validation
* The LLM is untrusted. Every tool call payload generated by the LLM must be strictly validated with Pydantic models before execution.
* If the LLM generates a non-existent `product_id`, negative `quantity`, or invalid filter key:
  * Reject the execution deterministically.
  * Feed an error message back into the LangGraph state loop to prompt self-correction without raising unhandled backend exceptions.

## 3. Memory & Token Budget Limits
* Conversation history must implement sliding-window token management or periodic summarization.
* Unbounded conversation contexts that could lead to Out-Of-Memory (OOM) or exorbitant LLM costs are prohibited.
* Max history per active session: Last 10 turns retained verbatim; older context compressed into semantic user profile memory.

## 4. Connection Pooling & Resource Caps
* Database connection pools must have explicit caps:
  * `pool_size`: 20
  * `max_overflow`: 10
  * `pool_timeout`: 30s
* Use connection recycling and health check pings before checkout.
* Background workers (e.g. embedding updates, telemetry logging) must be offloaded asynchronously without blocking shopper responses.
